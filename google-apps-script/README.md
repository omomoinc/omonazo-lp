# オモ謎LP：シートの「ビルド」操作で公開する

シート・Driveの編集だけではLPは変わりません。シートの **「LP更新 → 検証してビルド」** を実行すると、その時点の公開対象の本文・画像を保存し、Cloudflare Pagesへビルドを依頼します。成功すると静的HTMLと画像が公開されます。

```text
シートとDriveを編集 → 入力と画像を検証 → 検証してビルド
                                         ↓
                         本文・画像を保存したスナップショット
                                         ↓
                          CloudflareでHTML・画像を生成して公開
```

ボタン操作後にシートや画像を編集しても、保存済みの内容は変わりません。次のビルド操作で取り込みます。連続依頼は1分以上空け、前回の公開結果を確認してから次を依頼してください。複数依頼が待機している場合、ビルド開始時に取得するのは最新の依頼のスナップショットです。

## 1. シートと画像フォルダ

今回の接続先（2026-10-11確認）：

- [導入実績入力シート](https://docs.google.com/spreadsheets/d/1nYl0qsqZ3Kd_2xG9qNsUutLPxG8yXwteIypKv2Hcc0Q/edit)：入力タブ名は `実績入力`、見出しは6行目。
- [導入実績画像フォルダ](https://drive.google.com/drive/folders/1zy2lnhyEIVLm6riMzqs1eH0psAuW_Umd)：既存実績の `case-*.jpg` 12枚を確認済み。再アップロードは不要です。

接続先の確認のみ完了しています。シート編集、Apps Script配置・認可、Cloudflare接続と本番ビルドは未完了です。

1. 上記の既存Googleスプレッドシートを使います。新規のシート作成やテンプレートの再インポートは不要です。
2. 見出し行（テンプレートでは6行目）のI〜K列へ、順に `公開状態`、`表示順`、`画像代替テキスト` を追加します。見出し名は完全一致。列順は変更できます。
3. 上記の既存画像フォルダを使います。画像は直下に置き、同じ名前を複数作らないでください。
4. シートと画像フォルダを更新担当者の個別アカウントへ共有します。どちらも一般公開は不要です。

| 列 | 入力内容 |
| --- | --- |
| エリア | 全県・北信・中信・東信・南信・その他。全県は県全域の案件で、全エリアの合算ではありません |
| 市町村名・開催地域 | 必須 |
| クライアント名 | 任意。「様」はLPが付けます |
| イベント名 | 必須 |
| カテゴリ | 複数は半角カンマ区切り |
| 説明文 | 必須 |
| 画像ファイル名 | 拡張子を含め完全一致。空欄なら画像なし |
| 詳細URL | 任意。http / https のURL |
| 公開状態 | `公開` の行だけをビルド対象にします。その他は除外 |
| 表示順 | 半角数字、小さい順。同値は行順。空欄は行番号 |
| 画像代替テキスト | 写真の内容を表す短い説明。任意 |

画像はJPEG・PNG・WebP、1枚800 KiB以下、公開画像の合計10 MiB以下。目安は横1200px・100〜300KBです。サブフォルダ、重複ファイル名、SVG・GIF・HEICは未対応。画像の不足や入力エラーがあればビルド依頼を中止します。管理メモなどの追加列は配信しません。

## 2. Apps Scriptを配置する

1. シートの「拡張機能 → Apps Script」で、`Code.gs` を貼り付けます。シートに紐づくスクリプトとして配置してください。
2. 「プロジェクトの設定 → スクリプトプロパティ」へ以下を設定します。

| キー | 値 |
| --- | --- |
| SPREADSHEET_ID | `1nYl0qsqZ3Kd_2xG9qNsUutLPxG8yXwteIypKv2Hcc0Q` |
| SHEET_NAME | `実績入力` |
| IMAGE_FOLDER_ID | `1zy2lnhyEIVLm6riMzqs1eH0psAuW_Umd` |
| BUILD_API_TOKEN | 32文字以上のランダムな秘密文字列。Cloudflare側の `CASES_BUILD_TOKEN` と同じ値 |
| CLOUDFLARE_DEPLOY_HOOK | Cloudflare PagesのDeploy Hook URL。次の節で作成 |

`BUILD_API_TOKEN` とDeploy Hook URLをシートのセルやGitHubへ記載しないでください。トークンはローカルで `openssl rand -hex 32` などで生成できます。Cloudflareの環境変数設定にのみコピーします。

3. 今回は画像12枚がアップロード済みのため、そのまま使用します。`InitialCases.gs` を同じプロジェクトへ追加して `importInitialCases` を一度実行します。既存入力があれば上書きせず中止します。12件は下書きで入ります。
4. 内容確認後、対象行の公開状態を `公開` にします。`validateCases` を実行し、必要なSheets・Drive権限を承認して検証OKを確認します。この操作では公開しません。
5. 「デプロイ → 新しいデプロイ → ウェブアプリ」で「実行するユーザー：自分」「アクセスできるユーザー：全員」を選び、末尾 `/exec` のURLを取得します。公開するのはビルド用APIで、データ取得にはトークンが必要です。GETやトークンなしのPOSTはデータを返しません。
6. Google側のコード変更時は「デプロイを管理 → 編集 → 新しいバージョン」で更新します。スプレッドシートを再読み込みすると「LP更新」メニューが表示されます。

組織ポリシーで匿名アクセスを許可できない場合、Workspace管理者への確認または認証方式の変更が必要です。初回のビルド操作では、外部通信の権限承認も求められます。

## 3. Cloudflare Pagesを接続する

GitHubでコードを管理し、Cloudflare PagesのGit連携で公開します。

| 設定 | 値 |
| --- | --- |
| Framework preset | None |
| Root directory | この `web` フォルダに相当するリポジトリ内のパス。ここがリポジトリルートなら空欄 |
| Build command | `npm run build` |
| Build output directory | `dist` |
| NODE_VERSION | `22` |
| CASES_API_URL | Apps Scriptの `/exec` URL |
| CASES_BUILD_TOKEN | Google側の `BUILD_API_TOKEN` と同じ値。秘密の環境変数として登録 |

1. このコードをGitHubへpushし、Cloudflare Pagesプロジェクトを接続します。環境変数はProductionに設定してください。Previewを使うならPreviewにも設定が必要です。
2. プロジェクトの「Settings → Builds → Add deploy hook」で、公開ブランチ（例 `main`）用のDeploy Hookを作成します。
3. URLをApps Scriptの `CLOUDFLARE_DEPLOY_HOOK` に設定します。
4. シートの「LP更新 → 検証してビルド」を実行して、Cloudflareのデプロイ履歴で成功を確認します。最初のGit連携時には保存データがまだ存在せずビルドが失敗することがあります。この操作が初回の公開データを保存して再ビルドします。
5. **ボタンだけで公開タイミングを管理する場合**は、CloudflareのBranch controlで「Enable automatic production branch deployments」をオフにし、自動PreviewもNoneにします。Gitへのpushだけで自動公開しない設定です。設定変更後、Deploy Hook経由の手動ビルドが動くことを実機で確認します。

Cloudflare側で手動再試行した場合も、最後に保存されたスナップショットを使用します。編集中のシートは読みません。認証・取得・画像検証・HTML生成が失敗したビルドは非ゼロ終了し、従来の公開サイトは維持されます。トークン未設定時に見本データで本番公開することはありません。

## 4. シート内に「ビルド」ボタンを置く

メニューに加えて、大きなボタンも配置できます。

1. シートの「挿入 → 図形描画」で「検証してビルド」と書いた図形を作ります。
2. 図形のメニューから「スクリプトを割り当て」を選び、`requestBuild` と入力します。括弧は付けません。
3. クリックすると確認画面が出ます。実行すると検証・保存・ビルド依頼を行います。

検証だけのボタンなら `validateCasesFromMenu` を割り当てます。図形ボタンからのスクリプト実行はPCのWebブラウザ用です。Google Sheetsのモバイルアプリでは動作しません。

## 5. 日々の更新と公開確認

1. Driveへ画像をアップロードし、シートを編集します。編集だけでは公開されません。
2. 対象行の公開状態を `公開` にします。下書きや非公開行を除いた内容が次のビルド対象になります。
3. 「LP更新 → 入力と画像を検証」で入力チェックします。
4. 「検証してビルド」を実行し、Cloudflareで成功した後にLPを再読み込みして確認します。

「ビルド依頼を受け付けました」は公開完了ではありません。メニューの「前回のビルド依頼を確認」は依頼日時・件数・受付状況を表示します。公開の成否はCloudflareのデプロイ履歴で確認します。通信応答を確認できなかった場合、依頼が届いている可能性があるため、連打せずデプロイ履歴を確認してください。

同名画像を差し替える場合はDriveの「版を管理」を使うか、古いファイルを移動してから新しいファイルを置きます。次回のビルドで画像の内容から新しいURLを生成するため、古い画像キャッシュを避けられます。公開後にDrive上の画像を削除しても、次のビルドまでサイトの画像は変わりません。

シート編集者は原則ビルド操作もできる運用です。社員だけに公開操作を限定する必要がある場合は、公開担当の認証と編集用シートを分ける追加設計が必要です。列の保護だけではスクリプトの実行権限は制限できません。

保存ファイルは画像フォルダ内の `_omonazo_build_日時.json` です。画像データも含むため、ビルド回数に応じてDrive容量を使います。自動削除はしません。整理する場合は、`BUILD_SNAPSHOT_ID` が指す最新ファイルを必ず残し、必要な履歴も保管してください。自動生成プロパティの値は通常変更不要です。

## 6. SEO・開発者向け確認

- ビルド成果物は `dist/`。`index.html` ソースそのものを直接公開しないでください。
- 全公開実績の本文はHTMLに埋め込みます。閲覧者は「掲載実績を一覧で見る」から全件を確認できます。エリア切り替えUIも維持しています。
- 画像はDriveからビルド時に取得して `assets/images/cases/` へ保存し、通常の `<img src>` で配信します。本文・画像の閲覧にGoogle APIへの接続は不要です。
- 従来のブラウザ定期取得・JSONP APIは廃止しました。Google側に古いデプロイが残っていれば、新しい版へ更新するか旧版を停止してください。
- `npm test` で入力・画像・認証・スナップショット・ビルド依頼・HTML生成のテストを実行します。
- `npm run build -- --local` で既存12件を使ったローカル見本を生成できます。Cloudflare上ではこのモードを拒否します。
- Google認可、匿名POSTのリダイレクト、実際のDeploy Hook、シートのメニュー・図形ボタンは接続後の実機テストが必要です。
- 本番では「編集だけでは変わらない」「ボタン後に反映」「ボタン後の追加編集は含まれない」「下書きは出ない」「0件公開で旧実績が残らない」「エラー時は旧版維持」を確認します。
